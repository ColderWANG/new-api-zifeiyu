# 每日游戏中心与导航配置

本文记录每日游戏奖励、游戏中心设置与导航配置。翻译台基础功能见提交 `1725daf10`。游戏设置位于侧边栏模块下方；生图台和翻译台只保留导航显示配置，不再使用独立功能开关。生产部署需单独执行发布流程。

## 当前奖励规则

- 每个账号每天只能开始一局，限时 180 秒，北京时间（UTC+8）00:00 重置。
- 没有拾取绿色 Token：奖励为 0。
- 首个实际拾取的绿色 Token：默认奖励 5 USD 面值额度。
- 后续每个绿色 Token：默认奖励 0.5 USD 面值额度。
- 三个 Token 的奖励为 6 USD；当前生成规则最多产生 187 个掉落，拾取奖励的单局理论上限为 98 USD。
- 按绿色物件数量计奖，普通 Token 的内部数值 10、Boss Token 的内部数值 100 仅用于游戏积分，不作为奖励倍数。
- 服务器确认拾取数量，对局结束后一次性入账。失败或主动结束都结算已拾取奖励；主动结束仍消耗当天机会，且不进入排行榜。
- 已经开始的旧版本对局保留原结算规则，历史积分和已发奖励不重算。

周排行榜支持第一、第二、第三名的独立固定金额，合计自动计算。新配置保存后仅前三名获得周榜奖励，每周一 00:05（UTC+8）后结算。未保存新配置的旧周期沿用原先前三名对应的金额，但所有未结算周期都仅奖励前三名，同分时先完成者优先；已结算历史不重算。

## 管理员入口

1. **系统设置 → 站点与品牌 → 游戏中心**，位于“侧边栏模块”之后，地址 `/system-settings/site/game-center`：
   - 游戏中心功能开关。
   - 游戏额度奖励开关、首个 Token 金额、后续 Token 金额、每日总预算，以及周榜第一、第二、第三名奖励。周榜奖励总额由三个金额自动相加。
   - 金额按照站点余额显示单位编辑，复用既有额度换算，不要求管理员填写内部 quota 数字。
2. **系统设置 → 站点与品牌 → 顶部导航**：游戏中心的顶部入口显示开关。
3. **系统设置 → 站点与品牌 → 侧边栏模块**：生图台、翻译台、游戏中心分别显示或隐藏，不再共用游乐场键。

游戏功能开关与导航显示开关独立：隐藏入口仍可通过地址访问。游戏中心停用后阻止新对局，已开始的对局仍可续玩、刷新恢复和结算。管理员设置接口在游戏关闭后仍然可用。生图台、翻译台由侧边栏配置控制入口显示，旧 `studio_setting.*` 值不再阻止页面或请求；历史配置数据不删除。旧 `/system-settings/site/studios-games` 地址重定向到新的游戏中心设置页。

个人侧边栏偏好也补充上述三个入口；个人配置只能进一步隐藏管理员允许显示的内容。搜索菜单采用同样的可见性过滤。

## 预算与持久化

- 默认奖励关闭；配置中的默认金额为首个 5 USD、后续 0.5 USD。
- 每日总预算为 0 表示不设置总额上限。每日金额与预算在当天首次启用奖励的对局开局时保存快照，此后的修改在下一日生效。奖励关闭时创建的空白周期不会固定为零；管理员开启后，新对局可在当天使用配置中的奖励。周榜固定金额保存后立即更新本周未结算的奖励记录；其他周和已结算记录不变。关闭额度奖励不会取消本周已经启用的周榜奖励。
- 有预算上限时，开局先预留按当前规则可能得到的最高奖励。预算不足时不开局、不消耗当天次数；结算后释放未使用的预留额度。
- 游戏金额、预算、游戏开关与本周未结算的周榜金额在同一数据库事务中保存，失败时全部回滚，提交成功后再更新配置缓存。保存请求不包含生图台和翻译台配置。
- `game_periods` 新增 `weekly_reward_version` 与三个周榜金额字段。版本 0/1 兼容旧记录中的前三名金额，不再发放第 4–10 名奖励；版本 2 直接发放三项固定金额。前台合计仅包含实际可发放的三个名次。下一周的配置修改不会改变上一周待结算的金额；重复结算仍使用唯一流水防止重复入账。
- `GET /api/user/game/rewards` 仅限网页登录会话，返回奖励与本周信息，不读取或推进当前对局。前台每 5 秒轮询，切回窗口时刷新；保存页面会立即刷新同一客户端的奖励缓存。奖励刷新不会重新安装游戏状态或丢弃待提交操作。
- `game_runs` 的 `(user_id, day)` 唯一约束限制每日次数；`game_rewards` 的唯一流水与钱包更新在同一事务，重复请求不重复入账。
- 新对局使用奖励版本 2，记录首个和后续奖励快照及预留额度；已有对局保持开局时规则，不重算已发奖励或恢复当天次数。
- `game_periods.rewards_initialized` 标记当天奖励规则是否已启用，默认 false。升级时已有金额、预算、预留或已用额度的记录仍视为已初始化，不改写；只有尚未使用奖励的空白日周期可初始化。即使管理员主动把已启用奖励设为零，初始化标记也防止反复启用重置当天规则。该迁移仅新增布尔列，不删除旧字段或历史数据。
- 游戏页面展示新对局的有效奖励；本局规则不同时单独注明本局金额，实时预计奖励及最终结算仍按本局快照计算。
- 每分钟完成过期对局并释放预算；使用原额度缓存同步方法和金额日志格式。

## 接口与模拟

- 游戏 API 只允许网页登录会话，拒绝个人访问令牌。修改配置额外要求 Root 权限。
- 生图工作台继续使用 `/pg/image-studio`，保留网页登录认证、模型校验与原有扣费流程。
- 翻译台使用独立 `/pg/translation-studio`，复用原游乐场的网页登录认证、模型选择、分组校验、转发及扣费流程。
- 导航配置不影响用户正常使用 `/v1` API。
- 游戏采用 Go 权威模拟与 TypeScript 本地预测，100ms 固定步长，每两秒提交一次操作；计分与奖励不接受客户端直接上报。
- 关闭或刷新不会暂停计时。超过五秒的操作空档按无操作推进，奖励展示采用服务器已确认的拾取数。

## 周榜版本升级与恢复

新增字段以默认值 0 兼容旧数据库，旧奖励流水、余额和历史周记录不改写。写入版本 2 周榜规则后，旧应用不认识固定前三名金额，不能未经审核直接回退旧应用并让它结算这些记录；需要使用兼容该奖励版本的程序，或先完成恢复方案评审。旧版本也可能恢复向第 4–10 名发奖，因此未结算周期的结算行为同样需要审查。升级脚本的数据库变更保护仍须保留。
