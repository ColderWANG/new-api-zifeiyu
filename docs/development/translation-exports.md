# 翻译台新文件导出

PDF 与图片导出使用译文重新排版，不读取原页面图像作为底图，不绘制原文遮盖块。原背景、插图及复杂版式不保留；上传的原文件不会被修改。下载继续使用原文件类型及目标语言文件名。

- PDF 通过嵌入字体和文字绘制指令生成，文字可选择和复制；按段落换行，内容超出页面时继续分页，不缩小到原文小框内。
- 图片在干净画布上排版译文，必要时增加高度，并按 PNG、JPG、JPEG、WebP 对应编码导出。
- DOCX 继续替换原压缩包内的文字节点，保留已有文档结构、表格、图片和样式；TXT、Markdown 保留其原格式。
- PDF/图片的部分结果只包含已完成译文；DOCX 部分结果仍保留尚未翻译的原文。部分下载统一带 `partial` 标记。

字体位于 `web/public/static/translation-fonts/`，按导出内容从本站加载，不向第三方字体服务传输文档。原始许可证、固定来源和派生字体处理说明一并保留。中文及符号字体使用静态 TrueType 和双字节字形对齐，避免字体子集生成时出现缺字。`export-fonts.test.ts` 验证子集的每个字形轮廓与源字体一致。

排版保持 Unicode 字素簇完整，处理阿拉伯语等从右向左文本与数字混排；绘制采用视觉坐标、逻辑文本顺序，避免复制时词序颠倒。单次导出超过 200,000 字符、200 个 PDF 输出页面或图片尺寸上限时会明确报错，已生成译文仍可复制。

验证包含中文、阿拉伯语、表情符号、长译文自动分页、PNG/JPG/JPEG/WebP 真正的文件编码，以及 DOCX/TXT/Markdown 回归。测试 PDF 无原页面图片对象，嵌入字体可解码且译文可提取。浏览器验证使用固定模型响应，不调用付费上游。

Windows 本地构建时应使用 64 位 Go 主机工具链（可用 `go env GOHOSTARCH` 检查）。本次默认的 32 位链接器在嵌入前端资源时触发了内存上限；同版本 64 位 Go 配合发布参数 `-s -w` 已验证通过。仅设置目标 `GOARCH=amd64` 不会更换主机链接器。


## 2026-10-19 Ministral 真实调用验证

使用 ministral-8b-latest 完成 17 项代表性场景，覆盖直接输入及 TXT、Markdown、DOCX、PDF、PNG、JPG、JPEG、WebP；另完成 11 项输入/清除检查和 5 项停止、重试、故障保留、手机端、语言互换流程检查。文件核验包括实际编码、PDF 文本提取与渲染、DOCX 结构/样式/图片保留及 LibreOffice 打开。测试样本均为虚构内容。

本次发现并修复：

- 混合 PDF 页不能只凭存在文字层就忽略其中图片。检测 PDF 图像操作后，包含图片的页面整体交给视觉模型，纯文字页仍使用结构化文字翻译。
- Ministral 的 OCR 结果有时使用裸数组，现接受 regions 对象和等价裸数组两种包装；仍严格验证文本、坐标及数量，DOCX 的 ID 列表校验不放宽。

已知问题与限制：

- 阿拉伯语 PDF 中的 lam-alef 连字在实际 PyMuPDF 与 PDF.js 文本提取中出现顺序差异（译文中的“لا”变为“ال”）；视觉阅读正常，复制一致性尚未解决。不要把此前短句字体验证等同于所有阿拉伯语文本均可靠。
- 术语偏好属于模型软约束，本次有指定产品名仍被部分翻译的例子。
- DOCX 内嵌图片按原样保留，图片内文字不进行 OCR 翻译。
- 本机 Word 自动化没有完成，因此仅记录 LibreOffice 打开/渲染通过，不宣称 Microsoft Word 原生验证通过。

翻译台 65 项回归测试、类型检查、前端构建和 Go amd64 构建通过。工作区 artifacts/translation-real-ministral/REPORT.md 保存逐项结论，样本包只包含虚构源文件、实际导出与视觉证据，不包含数据库、凭据或运行日志。本次修改未推送、未部署线上。
